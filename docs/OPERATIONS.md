# دليل إعداد أول عميل / نسخة التجربة
## متطلبات
Windows 10/11 x64 مدعوم، شاشة 1050×700 على الأقل، مساحة1GB للبرنامج ومساحة إضافية للبيانات والنسخ. قارئ باركود USB keyboard wedge، طابعة حرارية80مم بتعريف Windows مناسب. لم يُجر اختبار فعلي على طابعة أو قارئ مادي. المثبت غير موقّع.
## تجربة التطوير
Node24 وnpm وGit. نفذ npm ci ثم npm run dev:hub في نافذة طرفية. المحاكي يستمع على127.0.0.1 فقط ويولد مفتاح توقيع داخل dev/keys المتجاهل في Git. في طرفية أخرى:
```powershell
$env:DAIDAR_DEV_HUB='1'
npm start
```
ابدأ التفعيل، وافق في المتصفح، ارجع واضغط التحقق. أنشئ اسم المنشأة والمدير وكلمة مرور10 أحرف أو أكثر. سجل دخول المدير. المحاكي لا يحتوي حساب مالك أو دفع، ولا يمثل تكاملًا تجاريًا.
## ملف التثبيت التجريبي
npm run package:pilot بعد تشغيل المحاكي مرة لتوليد المفتاح. يحتوي مفتاح تحقق عام فقط، ويعرض وضع التجربة. شغّل المحاكي نفسه ثم افتح التطبيق المثبت وفعّل من المتصفح. إذا بُني المثبت على جهاز مختلف عن المحاكي، شغّل التطبيق من طرفية يكون مجلدها الحالي جذر المستودع؛ نسخة التجربة تقرأ dev/keys/public.pem العام لهذا المحاكي من المجلد الحالي. استخدم نفس طريقة التشغيل لاحقًا لهذا الاختبار. لا تنسخ المفتاح الخاص إلى التطبيق. لا توزع نسخة المحاكي على عملاء تجاريين. لا مفاتيح خاصة داخل installer.
بناء الإنتاج: اضبط DAIDAR_HUB_URL وDAIDAR_LICENSE_PUBLIC_KEYS (JSON kid إلى PEM عام) عند npm run package:win. يفشل التفعيل دون خادم ومفاتيح أصلية. لا يوجد fallback تلقائي إلى المحاكي.
## رحلة المتجر
1. من المستخدمين أنشئ cashier بكلمة مؤقتة؛ يسجل محليًا ويغيرها قبل أي عمل.
2. من المنتجات أضف باركود ووحدة وعبوة ومعامل12 وسعر وتكلفة. معامل العبوة يمثل عدد وحدات أساسية، يُخزن بألف وحدة.
3. أضف موردًا من العملاء والموردين. شراء كرتونة كمية1 وسعر إجمالي للكرتونة، آجل للمورد؛ النقدي يحتاج وردية ممولة.
4. افتح وردية بعهدة نقدية. في الكاشير امسح باركود ثمEnter أو اضغط المنتج. F2 بحث، F8 اعتماد. السلة تدعم قطعة/عبوة وسعر الوحدة المختارة.
5. الخصم وتعديل السعر والآجل للمدير؛ الكاشير يبيع بالسعر المسموح. أدخل المدفوع نقدًا/بطاقة/أخرى أو الباقي نقدي. المبلغ المدفوع يجب ألا يزيد الإجمالي؛ لا تكامل بوابة بطاقات.
6. اعتماد ثم طباعة يفتح تعريف الطابعة. لا تعني عودة driver نجاح الورقة فعليًا. الإعادة من الفواتير بسبب، وتُسجل.
7. مرتجع من المستند الأصلي بالكمية الأساسية، جزئي أو كامل بجميع السطور؛ يعيد تكلفة وسعر الأصل. يمنع مرتجع يتجاوز المتبقي.
8. جرد: أدخل العدد الفعلي الأساسي وسبب، يسجل فرقًا. أغلق الوردية بالنقد المعدود وسبب الفرق.
9. تقارير الفترة UTC تظهر المبيعات وتكلفة المبيعات والربح الإجمالي؛ ليست صافي ربح.
10. نسخة يدوية إلى قرص خارجي. استعادة عبر المدير وكلمته وسبب وملفSQLite؛ البرنامج يحفظ نسخة أمان ثم يغلق الجلسة. الرخصة والتثبيت لا يستعادان من نسخة النشاط.
## البيانات والإزالة
بيانات الإنتاج في %APPDATA%/Daidar Flow، وبيانات المثبت التجريبي في %APPDATA%/Daidar Flow Pilot، خارج التثبيت. إزالة NSIS لا تحذف بياناتك تلقائيًا. النسخ اليومية في backups، تحفظ كل يوم بلا سياسة حذف آلية؛ راقب المساحة. النسخ المحلية غير مشفرة؛ احفظها بمكان مخول. لا نسخ سحابي منفذ.
## استيراد وتصدير
استيراد JSON مصفوفة منتجات بنفس fields في docs/products-example.json (قروش وألف وحدة). معاينة وأخطاء باركود/حقول قبل اعتماد ذري. تصدير JSON قراءة شامل للأعمال دون hashes أو رخص/أسرار؛ ليس صيغة استعادة، فالاستعادة منSQLite.

## المخطط والتحديث
المخطط الحالي2. ترقية1 إلى2 تحفظ نسخة VACUUM INTO متسقة قبل migration وتملأ snapshots لهوية الأصناف. استعادة البرنامج الحالية تقبل نسخ المخطط2 فقط؛ احتفظ بالبرنامج والنسخ القديمة لاختبار تحويلها قبل استعادتها. لا تنزيل تلقائي للتحديث، ولا حذف بيانات العميل عند الترقية. استيراد المنتجات يدعم وحدة أساسية وعبوة واحدة لكل منتج في هذه النسخة. كشف الشاشة يعرض أحدث300 مستند؛ التصدير الكامل والتقارير لا يستخدمان هذا الحد.

## إعادة اختبارات المثبت
بعد npm run package:pilot، نفذ scripts/installer-smoke.ps1 في PowerShell. يثبت نسخة التجربة في test-results/installed-pilot ثم يزيلها، ويحتفظ ببيانات ملف تعريف التجربة. لا تستخدمه على جهاز عليه جلسة نشطة من نسخة التجربة؛ أغلقها أولًا. يقرأ scripts/installer-ready.cjs سجل بدء الواجهة للتحقق من التشغيل.
